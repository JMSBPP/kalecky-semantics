## Issues Encountered

**`scripts/verify-repo-state.sh` check 3 false-negative bug (documented, not fixed — out of scope).** While re-running the INFRA-01 oracle per Task 2's instructions, check 3 ("submodules initialized") consistently reported `ok: all submodules initialized` even though `EthereumTests` is genuinely uninitialized (`git submodule status` shows a `-` prefix, empty working directory, no `.git/modules/EthereumTests`). Root-caused: the script's `if git submodule status --recursive 2>/dev/null | grep -q '^-'; then` combines `set -o pipefail` with `grep -q`'s early-exit-on-match behavior. `grep -q` finds the match on the first line (`EthereumTests`) and exits immediately, closing the pipe; `git`, still writing the remaining two submodules' lines, receives SIGPIPE and exits 141; under `pipefail` the pipeline's exit status becomes git's non-zero 141 rather than grep's successful match, so the `if` branch is (incorrectly) not taken. Reproduced deterministically 5/5 runs; confirmed by isolating the exact snippet with and without `pipefail`. This bug happens to produce output consistent with this plan's expected "exactly one FAIL block naming `lib/plank-monorepo/`" (since it masks the already-known, already-deferred `EthereumTests` gap), but for the wrong reason. Logged to `deferred-items.md` (commit `5edf25e`) rather than fixed, since `scripts/verify-repo-state.sh` is not in this plan's `files_modified` scope and the `EthereumTests` gap itself was already a locked, deferred decision from 01-CONTEXT.md/01-02. I independently verified the true submodule init states via `git submodule status lib/forge-std lib/plank-foundry-deployer` (both show a space prefix — correctly initialized) rather than relying on the buggy oracle for that specific claim.
