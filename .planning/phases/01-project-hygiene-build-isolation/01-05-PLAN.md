CRITICAL verified facts about the local `lib/plank-monorepo` copy (checked live during planning, 2026-08-15) — these are NOT in 01-RESEARCH.md and they change what a naive `git add` does:

1. **Five dangling gitdir pointers.** `lib/plank-monorepo` has no `.git` directory, but five of its nested dependency directories still contain a `.git` FILE (71-byte gitfile) pointing into a `lib/plank-monorepo/.git/modules/...` path that no longer exists:
   - `plankc/plank-diff-tests/lib/{forge-std,solady,plank-foundry-deployer}/.git`
   - `plankc/sir/sir-solidity-diff-tests/lib/{forge-std,solady}/.git`
   Because the gitdir target is missing, git currently treats those directories as ordinary directories rather than submodules — but any operation that repairs or recreates `lib/plank-monorepo/.git` would flip them into gitlinks (Pitfall 1 territory). They must be deleted before vendoring.

2. **`plank-diff-tests/lib/` is self-ignored.** `lib/plank-monorepo/plankc/plank-diff-tests/.gitignore` line 3 is `lib/`. Verified with `git check-ignore -v`:
   `lib/plank-monorepo/plankc/plank-diff-tests/.gitignore:3:lib/	lib/plank-monorepo/plankc/plank-diff-tests/lib/solady/src/Milady.sol`
   Consequence: a plain `git add lib/plank-monorepo` stages only **825** of the **1401** on-disk files, silently omitting the whole `plankc/plank-diff-tests/lib/**` tree — which is exactly where `remappings.txt` line 4's `solady/` target lives. Verified via `git add --dry-run lib/plank-monorepo | wc -l` -> `825`.
   `plankc/sir/sir-solidity-diff-tests/lib/**` is NOT ignored and does get staged.

3. `remappings.txt` line 4 is `solady/=lib/plank-monorepo/plankc/plank-diff-tests/lib/solady/src/`; representative files under it today include `utils/Base64.sol` and `tokens/ERC20.sol`.
